# 07 · Debugging and troubleshooting

> Linux/macOS-specific problems (sudo, certificate, root, proxy): `13-linux-and-macos.md` §9.

## Verbosity levels

| Option | Effect |
|--------|--------|
| (none) | main steps, tables, warnings and errors |
| `-v` | details (e.g. every claim, scan progress, reasons) |
| `-vv` or `--debug` | debug traces and the **full traceback** instead of the short message |

Always available (even afterwards, when the screen output is gone):
```powershell
claimcheck events --limit 100 --level WARN     # persistent journal (levels: INFO WARN ERROR STEP OK)
claimcheck show attempts                        # every attempt: status, notes, excluded
claimcheck show raw_files                       # raw files: lines imported, complete yes/no
claimcheck sql "SELECT phase, status, note FROM attempts ORDER BY id DESC LIMIT 10"
```
Files: `runs\<app>\<run>\logs\claimcheck.log` (everything, including DEBUG) and `logs\mitmdump-*.log` (mitmproxy output).

## Crashes and restarts: what happens to the data

| Event | Effect | What to do |
|-------|--------|------------|
| Ctrl+C during capture | stops mitmdump, imports the JSONL; phase `partial` (stopped early) or `done` (phase without a duration) | nothing |
| The PC shuts down / process killed | lines already written to `raw\*.jsonl` are kept; the last line may be truncated | run **any** write command again, or `claimcheck ingest`: it recovers the data, discards the truncated line, promotes the attempt to `partial` |
| Failed phase | attempt `failed` with the note; it does not replace an earlier good attempt | fix the cause and run again |
| Two commands at once on the same run | the second one refuses (`RunLocked`) | wait; if the first one died, the stale lock is released by itself |
| You import twice | no duplicates (UNIQUE constraint) | — |
| You re-run `report`/`export` | new file `-2`, `-3`… | — |

The database rejects `UPDATE`/`DELETE` on the result tables at SQL level: not even a bug can delete data.
If an orphaned `mitmdump` process is still writing, terminate it (`Stop-Process -Name mitmdump`) *before* `ingest`.

## Symptoms → causes

| Symptom | Likely cause | Remedy |
|---------|--------------|--------|
| `mitmdump not found` | mitmproxy not installed / venv not active | `pip install -e ".[capture]"`; or `capture.mitmdump: "C:\...\mitmdump.exe"` |
| "needs an elevated terminal" | `mode: local` without Administrator | reopen the terminal as Administrator (or `--allow-no-admin`, which usually fails) |
| "exe_name" missing | `app.exe_name` empty | Task Manager → Details, copy the exact name |
| No records captured | wrong process name; Tauri app (traffic from `msedgewebview2.exe`); app ignoring the proxy in `regular` | fix `exe_name` (several processes allowed), use `local`, check `logs\mitmdump-*.log` |
| Only `tls_failed`/`opaque_unknown` | certificate not installed, app's own certificate store, pinning | install the CA (see 02); if it is pinning, it is a limit: write it down |
| Port in use (`regular`) | another process on `listen_port` | change `capture.listen_port` |
| Capture stops by itself | resource guard (disk/`max_flows`) | read the attempt's note (`show attempts`), free space or raise the limit |
| `claims`: "no document could be loaded" | URL unreachable / non-text page / wrong path | check the WARN messages, save the page and use `type: file` |
| Zero promises extracted | text generated by JavaScript, or sentences not covered by the patterns | save the rendered HTML; the rules are in `claims.py` |
| `static` finds nothing | native/obfuscated app, wrong `install_dir`, limits too low | check the path, read the *coverage* (skipped files) |
| `database is locked` / odd errors | `runs\` in a synced folder; two processes | move `runs\` to a local disk |
| `Set-ExecutionPolicy` when activating the venv | PowerShell policy | see 02 §2 |
| Relative paths not found | resolved against the folder of the original manifest | use absolute paths |
| Surprising verdict | heuristic classification | `show labels` (reasons) and `show flows --all-columns` |

## Reporting a problem

Attach: `claimcheck version`, `claimcheck doctor`, the last lines of `claimcheck events --limit 50`, the traceback with `--debug`
and (if possible) `claimcheck export`. **Check first** that it contains no data you do not want to share.
